| 项 | 定稿 |

## 1. 现状实测（改动的依据）

### 1.1 CG 为什么"被压在 UI 和人物下面"

带 CG 的一拍，生成物 `maps/story/scenario.txt` 的节点顺序（例：L1917-2010）实测：

```
type=bg    id=背景            ← 最底
type=bg    id=CG              ← CG 只是个"背景类"节点
type=char  id=char_ds / char_glm / char_qianwen …
type=char  id=ui_vignette
type=bg    id=ui_dialog       （对话框底板）
type=dialog     对话文字        ← 内容节点，永远最上
type=bg    id=ui_nameplate
```

引擎把节点分成两类（`ReaderView.java:599-601`）：**舞台节点 = bg / char**，每拍被重新压到最底层（`ReaderView.java:531-536`）；**内容节点 = dialog / name / button / text** 永远在最上。净效果：

> 背景 < **CG** < 立绘 < UI 皮肤 < 文字与选项

`tools/build_story.mjs:805` 的注释写着"CG 层：放在背景之后、立绘之前 —— 天然是背景之上、立绘之下"⇒ 这是当初的**主动选择**，本期要改的就是它。引擎里没有任何针对 `id=CG` 的特判（全仓 Java 搜索 0 处）。

### 1.2 22 处 CG 的分布

| 情况 | 数量 |
|---|---|
| CG 拍 | 22 |
| 其中**同时有台词** | **17** |
| 同时有立绘 | 22 |
| 同时有 UI 皮肤 | 17 |
| 使用 `hold` 模式 | **0** |

### 1.3 立绘现状（硬数字）

| 项 | 值 |
|---|---|
| 素材 | `ds/base.png` = **603×1469**（w/h 0.41） |
| 节点框 | **320×520**，y=150；三档站位 x = **60 / 480 / 900**（`build_story.mjs:128-129`） |
| 等比适配后实际画出 | **213×520**，占画布宽 **16.6%** |
| 对话框顶边 | y = **516** ⇒ 立绘实际可见约 **366px**（头到大腿） |

### 1.4 素材画布**不统一**（这是"靠遮挡"方案的致命前提）

实测 16 个立绘：**15 种宽度、9 种高度**，w/h 从 0.41 到 0.61，另有横图与半身图：

| 素材 | 尺寸 | w/h |
|---|---|---|
| `ds/base.png` | 603×1469 | 0.41 |
| `xiguan/base.png` | 893×1463 | 0.61 |
| `scale_polite.png` | 1002×1493 | 0.67 |
| `bugs_normal.png` | 890×581 | 1.53（横图） |
| `paimon_cute.png` | 469×833 | 0.56（半身小图） |

后果：同一个框里做等比适配，`ds`(0.41) 会填满框，而 `xiguan`(0.61) 只按 0.526 缩放且**垂直居中 → 头顶低 188px、人小一圈**。两人同框必然穿帮 ⇒ **必须先归一化素材画布**，否则"不改引擎靠遮挡"不成立。

### 1.5 插件能力边界（为什么"取景几何"必须在数据里）

slot 插件今天只能 `setProperty(节点id, 属性, 值)`（`FlowHost.java:26`、`PluginContext.java:262`），**没有视图层能力**：不能裁剪、不能改 z 序、不能加节点；而且引擎每拍重排舞台节点，插件就算 `toFront` 也会被下一拍冲掉。

⇒ 结论：**取景几何 = 数据（编译器参数表）；演出与切换 = 插件动作。**

## 2. 定稿需求（可验收）

| ID | 需求 | 验收口径 |
|---|---|---|
| **R1** | 立绘常态取景 = 半身（到腰） | 全篇立绘节点框为 bust 几何；实机截图：人物可见区为头顶到腰，宽度 ≈470（现在 213） |
| **R2** | 需要时切全身 | 剧本写 `@pose <角色> full` 后，该角色后续拍为 full 取景；写 `bust` 切回 |
| **R3** | 角色登场全身亮相 | 剧本写 `@debut <角色>` ⇒ 产出一张**无台词卡拍**（背景 + 该角色全身，无对话框/名牌/暗角），点一下继续；下一拍回半身 |
| **R4** | 立绘素材画布归一化 | 归一化后所有立绘：同身高、脚线一致、中心 x 一致；同框两人头顶高度差 = 0 |
| **B1** | CG 盖住一切内容（含文字） | `@cg` 一律生成 **CG 独占卡拍**（背景 + CG，无立绘/无 UI 皮肤/无台词），点一下继续；原同拍台词顺延到下一拍，台词不丢 |
| **N1** | 非目标 | 不加引擎裁剪/层级原语；不改编辑器；不做登场自动判定；不重画素材（只补透明边距） |

**剧情侧需要学的新写法（就 2 条）**

```
@debut ds              ← 角色首次登场：全身亮相一拍（点一下继续），之后自动回半身
@pose ds full          ← 该角色切全身取景（持久，直到 @pose ds bust）
@pose ds bust          ← 切回半身（默认值）
```

## 3. 实施方案（4 个切片，各自独立可验收）

### S1 —— CG 拆拍（纯 bug 修复，先做）

| 项 | 内容 |
|---|---|
| 落点 | `tools/build_story.mjs`（`@cg` → 卡拍生成处，现 L805 附近与 L578-585 的 cgcard 逻辑） |
| 做法 | 每个 `@cg` 一律走"卡拍"：卡拍只含 `背景 + CG`；原同拍台词顺延到下一拍；卡拍沿用现有 flash 语义（点一下继续） |
| 影响面 | 22 处 CG（其中 17 处会拆出新拍，拍数 +17） |
| 验收 | 编译 0 解析警告；22 处 CG 所在拍 `type=char`/`ui_*`/`type=dialog` 计数均为 0；实机截图：CG 全屏无 UI 无文字，点击后出台词；台词总数不变（逐章比对） |
| 风险 | 节奏变化（多一次点击）；已确认接受。`hold` 语义另定（见 §5） |

### S2 —— 立绘画布归一化脚本

| 项 | 内容 |
|---|---|
| 落点 | 新脚本 `tools/normalize_sprites.py`（+ 分类映射表） |
| 做法 | alpha 裁边 → 等比缩放到统一身高 → 贴到统一画布（中心 x 固定、脚线固定）；**不改画风、不重画**，只补透明边距 |
| 规格（默认，可改） | 画布 **1024×1536**；角色身高 **1460**；脚线 **y=1500**；中心 **x=512** |
| 分类 | "全身类"走上述规格；"半身类"（bbox 高 < 1000px，如 `bugs_normal` / `paimon_cute`）单独一档画布，列表人工确认 |
| 验收 | 脚本 `--check` 报告：全部立绘 w/h 一致（全身类）；抽 2 个角色同框截图，头顶高度差 = 0；文件体积变化 < ±10% |
| 风险 | 归一化会改变 `path` 指向的文件内容（需备份/可回滚）；横图与半身图必须分类正确，否则会被拉高变形 |

### S3 —— 取景参数表 + 常态半身

| 项 | 内容 |
|---|---|
| 落点 | `tools/build_story.mjs`：`POS` / `CHAR_W` / `CHAR_H`（L128-129）升级为**取景参数表** |
| 参数 | `bust`（默认）与 `full` × 三档站位（左/中/右），每组给 `x,y,w,h`，数字直接可改 |
| 默认数值（基于 603×1469 素材） | **bust：470×1147 @ y=0** ⇒ 可见带 0..516 = 头到腰，宽度 213 → 470；**full：296×720 @ y=0**（脚仍在对话框后，若要真正全身可见用 `@debut` 卡拍） |
| 验收 | 全篇立绘节点几何 = bust 表；实机截图 3 张（左/中/右站位）人物头顶到腰、无裁切异常；站位之间不重叠 |
| 风险 | 归一化（S2）之后需要按新画布重算这组数字 ⇒ **S2 → S3 顺序执行**，S3 的数值以归一化后的画布为准 |

### S4 —— 插件动作 + 登场卡指令

| 项 | 内容 |
|---|---|
| 落点 | `src/main/java/com/studio/plugin/builtin/StagePlugin.java`（新增动作 `frame`）、`tools/build_story.mjs`（`@debut` / `@pose` 解析 + 卡拍生成）、`docs` 剧本写作说明 |
| 做法 | 插件 `cast \| frame \| 立绘_x \| bust\|full`：本质是 `setProperty` 一组 `x/y/width/height`（插件今天就有的能力，**零引擎改动**）；`@pose` 由编译器写成持久取景，`@debut` 产出卡拍 |
| 验收 | 单测：`cast\|frame` 对目标节点写入正确几何；实机：`@debut ds` 出现无对话框的全身亮相拍，点击后回半身；`@pose ds full` 后续拍为全身 |
| 风险 | `StagePlugin` 是编辑器自带插件，改动要同步 `PluginCatalog` 的用法文案（否则编辑器里看不到新动作说明） |

### 7.2 关键实测（决定"自适应"这个设计）

- 同台立绘数量分布：**6 人 116 拍 / 7 人 278 拍 / 8 人 85 拍 / 10 人 1 拍 / 11 人 63 拍**，
  有立绘的拍平均 **5.86** 人 —— 这就是原来立绘只有 213px 宽的原因（6×213 ≈ 1280 铺满）。
  一律放大到半身只会重叠成一锅，所以 bust 只在 105 个拍（1~2 人）生效。
- 取景档落地分布：bust 172 / mid 282 / small 512 / crowd 4025 个立绘节点，旧几何 320×520 残留 **0**。

### 7.4 剧情侧写作说明（就两条）

```
@debut <角色>            # 登场卡拍：该角色全身亮相的一拍（无对话框），点一下继续；之后回常态取景
@pose <角色> bust|mid|small|crowd|full   # 持久切换该角色的取景档；bust 为常态
```

- `@pose` 会**另起一拍**（取景是逐拍几何），所以别写在一段连续台词的中间，除非确实想在那里切镜。
- 常态取景是按人数自动选的，一般不用写；`full` 只适合"要看清全身"的场合（腿会被对话框压住，
  要完全可见就用 `@debut`）。

### 7.5 遗留 / 待美术侧

- **10 个素材是放大使用的**（归一化时 scale > 1.3，建议后续出更高分辨率版本）：
  `pikachu/*` ×3（1.46×）、`paimon/*` ×4（1.84×）、`bugs/*` ×3（1.41×）。
- 半身档下**站位靠边的角色会被画面裁掉一部分**（bust 框 960 宽、左右站位中心 250 / 1030），
  这是 VN 常见取舍；要收紧改 `FRAMES` 的 `s` 或 `STATIONS` 即可（单测会守住两边一致）。
- 编辑器（可视化取景面板）按约定本期未做；调取景目前靠 `build_story.mjs` 的表 + 重编译。
